# 리드필드 생성 컴퓨터 확인 요청

> 받는 쪽: `leadfieldF/M{j}.npy` + `inj_current.json` 을 만든 Sim4Life 프로젝트가 있는 컴퓨터
> 이 문서 하나로 무엇을·왜 확인하는지 파악되게 썼다. 다른 문서 없이 진행 가능.

---

## 1. 무슨 일이 있었나

리드필드를 쓰는 tTIS 플래너(TIP)에서 **심부 표적의 전기장이 문헌보다 4~6배 크게** 나온다.
시상 TI 엔벨로프가 총 2 mA 에서 **1.22 V/m** 인데 문헌 상한은 0.2~0.8 V/m 이다.

원인을 좁히려고 리드필드 자체를 전면 점검했다. 결과:

**정상으로 확인된 것 (여기는 문제 없다)**

| 항목 | 결과 |
|---|---|
| 좌표 디코딩 · 중첩 | E 벡터 독립 재현 오차 2.7e-08 |
| 정규화 규약 (`ΣI=0` 에서 Cz 기저 상쇄) | 자기정합 |
| 깊이 구조 | 피질p95/시상 = 3.4~4.0배 (문헌 3~5배) |
| 두개골 차단 | 뇌 양단 전위강하 7~12% (정상) |
| 표적 마스크 | 위치·크기 타당 |

**즉 구조는 멀쩡하고 절대 스케일만 어긋난다.** 상수배로 고칠 수 있는 문제다.

**과대 배수 — 서로 독립인 세 계열이 수렴**

| 근거 | 배수 |
|---|---|
| Lamoš 2025 STN 쌍극 LFP 실측 (100~300 µV) | 2.3 |
| Violante 해마 문헌 (0.26~0.5 V/m @2 mA) | 3~6 |
| TI 시상 문헌 | 5~8 |
| 전류 플럭스 `∮σE·dA` — 주입 1 mA 인데 통과 1.3~2.9 mA (**물리적 불가능**) | 4.5~9.7 |
| 동심 4구 해석해 (Sim4Life 자체 전도도) | **5.5~5.9** |

**수렴값 ≈ ÷5.**

## 1-2. ★가장 유력한 원인 — 재료 DB 선택

**균질구 상한 검사**가 결정적이다. 두개골·CSF 를 **아예 없앤** 균질구는 심부 필드의
물리적 **상한**이다(저항성 두개골도, 전도성 CSF 도 심부를 낮추므로).
머리 반경 78.9 mm, 대척 전극 1 mA, T7-T8 축 위에서:

| 축좌표(mm) | TIP | 균질구 σ=0.38 상한 | 초과 | 허용 최대 σ |
|---:|---:|---:|---:|---:|
| 60 | 2.964 | 1.307 | 2.27× | 0.168 |
| 50 | 2.709 | 0.629 | 4.30× | 0.088 |
| 40 | 2.050 | 0.394 | 5.21× | 0.073 |
| 30 | 1.128 | 0.287 | 3.92× | 0.097 |
| 20 | 0.979 | 0.234 | 4.17× | 0.091 |
| 10 | 0.544 | 0.209 | 2.60× | 0.146 |

**TIP 값이 물리적으로 가능하려면 모델의 뇌 전도도가 ≤ 0.07~0.17 S/m 여야 한다**
(두개골·CSF 를 넣으면 더 낮아야 하므로 이건 느슨한 상한이다).

| 후보 | σ_GM | 가능? |
|---|---:|---|
| IT'IS **LF** v5.0 | 0.4191 | ❌ 불가능 |
| SimNIBS/ROAST 관행 | 0.276 | ❌ 불가능 |
| **Gabriel 분산모델 저주파** | 0.03~0.11 | ✅ **이 대역만 가능** |

**Sim4Life 에는 전도도가 4배 이상 차이 나는 재료 DB 가 둘 있다.**

- `IT'IS LF` (db_id=4) — 저주파 전용 **스칼라** 값. v5.0 GM 0.4191 · WM 0.3480
- `IT'IS` (db_id=3) — **분산(Cole-Cole) 모델.** 시뮬레이션 주파수에서 평가된다.
  Gabriel ex-vivo 기반이라 **저주파에서 값이 훨씬 작다**(GM 0.03~0.11).

IT'IS 가 LF DB 를 따로 내놓은 이유가 바로 Gabriel 저주파 값이 in-vivo 와 안 맞기 때문이다.
**분산 DB 를 저주파에서 쓰면 E 가 3~5배 과대**해진다 — 우리가 보는 배수와 정확히 일치한다.

→ **확인 1순위는 "어느 재료 DB 를 썼고 시뮬레이션 주파수가 얼마였는가" 다.**

## 2. 확인할 것 — ①②가 유력하다

### ① 재료 DB 와 주파수 ★최우선

- 재료를 **`IT'IS`(분산)** 에서 할당했는가, **`IT'IS LF`(저주파 스칼라)** 에서 할당했는가?
  (Sim4Life 재료 창에서 DB 이름과 버전이 보인다)
- **시뮬레이션 주파수는 얼마였는가?** 분산 DB 를 썼다면 이 값이 σ 를 정한다.
- 실제 할당된 **σ 수치**를 조직별로 적어 줄 것 (뇌·CSF·두개골·두피 최소 4종).
  이 숫자만 오면 보정계수가 **바로 계산된다.**

기대값 — 우리 추정이 맞다면 뇌 σ 가 **0.03~0.11 S/m** 근처로 나올 것이다.
0.28~0.42 로 나온다면 원인은 ②③ 쪽이다.

### ② 주입전류를 어떻게 뽑았는가

`inj_current.json` 에는 **1 V 인가 시 주입전류 0.60~0.75 mA** 로 기록돼 있다
(전극당 값, 단위 A. 예: `"0": 0.0006697...`).
이 값으로 `unitnorm = 1e-3 / I_inj ≈ 1.49` 를 만들어 필드에 곱한다.

**확인 사항**

- 이 전류가 전극 **표면 전체**를 적분한 총 전류인가?
  아니면 한 면·일부 패치·특정 단면만 적분한 값인가?
- Sim4Life 에서 어떤 센서/표현식으로 얻었는가? (스크립트가 있으면 그 줄)

**왜 유력한가**: 이 값이 실제보다 작으면 `unitnorm` 이 커지고 필드가 그만큼 부풀려진다.
전극이 원기둥(r=4mm, h=2mm)이라 **옆면·윗면을 빼고 아랫면만 적분**했다면 딱 이런 일이 난다.

**참고**: 필드를 5배 낮추려면 참 주입전류가 **3.4 mA (R = 295 Ω)** 여야 하는데,
머리 저항으로는 너무 낮다. 즉 "R 이 원래 낮았다" 로는 설명이 안 되고,
**전류를 덜 세었다**는 쪽이 자연스럽다.

### ③ 여기(excitation) 조건

`M{j}.npy` 가 정말 **"전극 j = 1 V, Cz = 0 V, 나머지 59개 floating PEC"** 해인가?

- 인가 전압이 1 V 가 아니었다면 스케일이 통째로 어긋난다
- **전류원**이었다면 정규화 자체가 이중 적용된다
- 나머지 전극이 floating 이 아니라 접지(0 V)였다면 구조가 다르다
  (기록상 접지 기저는 "표적 |E| 64% 과대"로 폐기됐다고 돼 있다 — 혼입 여부 확인)

### ④ (①이 부정되면) 재료 할당 표 전체

- 어느 재료 DB·버전인가 (IT'IS / IT'IS LF, v3.1 / 4.0 / 4.1 / 4.2 / 5.0)
- **두개골이 어떤 재료로 잡혔는가** ← 심부 필드에 가장 큰 영향
  (`Skull` 0.0179 인가, `Skull Cortical` 0.0064 인가, 아니면 v4.0 의 0.32 인가?
  v4.0 의 `Skull Cortical` 은 **0.32 S/m** 로 v4.1 의 0.0064 보다 **50배** 크다.
  이게 잘못 잡혔다면 두개골 차단이 사라져 심부가 크게 과대해진다 — **강력한 후보**)
- 뇌·CSF·두피는 무엇으로 잡혔는가

가능하면 **재료 할당 표 전체**(조직 이름 → 재료 이름 → σ)를 그대로 떠 주면 좋다.

### ⑤ CSF·두개골 분할이 실제로 모델에 들어갔는가

우리가 받은 뇌 마스크(`blabel1010.npy`)에는 라벨이 GM·WM·심부핵뿐이고 **CSF가 없다.**
평가 격자에서만 뺀 것인지, **모델 자체에 CSF가 없었던 것인지** 구분이 안 된다.

CSF(σ=1.879)는 뇌를 감싸 전류를 옆으로 흘리는 층이라, 빠지면 심부 필드가 과대해진다.
→ 모델 엔티티 목록에 CSF·두개골·두피가 있는지 확인.

### ⑥ 출력 단위

E-field 센서 출력이 **V/m** 인가. (Sim4Life 기본은 V/m 이지만 확인)

## 3. 보내 주면 좋은 것

우선순위 순. **1번만 있어도 대부분 판정된다.**

1. **재료 할당 표** — 조직 → DB(IT'IS / IT'IS LF) → 버전 → σ(S/m), 그리고 **시뮬레이션 주파수**
2. **주입전류를 계산한 스크립트/설정** (또는 그 부분 캡처)
3. **모델 엔티티 목록** — CSF·두개골·두피 존재 여부
4. 시뮬레이션 설정 요약 — 여기 조건(전압/전류), 경계조건, 솔버 종류
5. 가능하면 **프로젝트 파일(.smash) 자체**. 이게 오면 여기서 직접 다 확인한다

## 4. 결정적인 한 방 — 전극 표면 플럭스 재적분

시간이 없으면 **이것만** 해도 된다.

전극 하나(예: T7)를 골라, 1 V 해에서 **전극 표면 전체를 감싸는 닫힌 면**의 전류
`∮ σE·dA` 를 다시 적분해 `inj_current.json` 값과 비교한다.

- **일치하면** → 주입전류는 정상. 원인은 ①(재료 DB) 쪽이 거의 확실하다
- **재적분값이 4~6배 크면** → **원인 확정.** `unitnorm` 을 그 값으로 다시 만들면 끝난다

전극 표면이 까다로우면 전극을 넉넉히 감싸는 **정육면체 상자**의 6면 플럭스를 재도 된다
(상자 안에 다른 전극이 없기만 하면 값은 같다).

## 5. 참고 — 여기서 이미 확인한 사실

- **Sim4Life 재료 DB 는 라이선스 없이 읽힌다.** `data/XMaterials/Materials.db` 가 그냥
  SQLite 다. 전도도 property_id 는 `19988968-6221-4d0f-abbc-01ee95bfc2e5`,
  db_id 는 3=IT'IS · 4=IT'IS LF.
- **라이선스는 모든 기능이 좌석 1개씩**이다. `lmstat.exe -a` 로 확인.
  다른 사람이 GUI 좌석을 쥐고 있으면 헤드리스 API 호출이 **에러 없이 그냥 멈춘다**(대기).
  응답이 없다고 버그로 오해하지 말 것.
- `practice1.smash` · `test.smash` 는 HDF5 로 직접 열어봤으나 **모델 전용**이라
  재료·시뮬레이션 설정이 없었다. 리드필드를 만든 프로젝트와는 다른 파일이다.

## 6. 이게 확정되면

`config.FIELD_SCALE` 상수 하나로 보정한다. **상수배라 상대 결론은 전부 보존된다**
— 방법 간 비교(classic·dual·분산·시분할), 초점성 순위, 각도 스윕의 위상 결론은
지금도 유효하고 보정 후에도 그대로다. 바뀌는 것은 **절대 V/m 값과 그로부터 나온
안전한계·역치 대비 비율·µV 예측**뿐이다.
