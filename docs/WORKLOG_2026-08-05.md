## 1. 각도 스윕 (`ANGLE_SWEEP_REQUEST.md` 대응)

### 과정

초판 스크립트는 방향당 286초 × 24방향 = **114분**이었다. 세 가지로 줄였다:

1. **전극쌍 차분 선계산** — `|Pt[a]−Pt[b]|` 는 쌍 C(40,2)=780종뿐인데 전수탐색은
   메타 274,170 × 비율 13번 재계산하고 있었다
2. **2단 탐색** — 성긴 점집합(표적 200/off 400) 전수 → 상위 6,000만 전체 점집합에서 정밀
3. **방향 병렬** — 워커는 리드필드가 필요 없고 투영값 `(K,N)` 배열만 받으면 된다

→ **2분**. 2단 탐색의 위험(탐색공간 축소가 결론을 뒤집은 전력)은 **승자의 성긴 단계 순위**를
출력해 통제했다 — 최악 1,942/6,000 으로 절단면에 여유가 있다.

### 정정한 것 3가지

**(a) 선별 자를 바꿨다.** 처음엔 목적함수 `Tdir(n̂)` 으로 각도를 골랐는데, n̂ 이 각도마다
달라 **각도끼리 견줄 수 없는 자**다(각 각도가 자기 방향에서 최고를 낸다). 점 뉴런 집단의
공통 자인 **배향 무작위 평균 Tdir** 로 바꿨다.

**(b) 극성 게이지를 고정했다.** 채널 양극/음극을 맞바꾸면 E₁ → −E₁ 이라 엔벨로프 위상이
통째로 뒤집힌다. M1·M2·M3 는 절대값 기반이라 **최적화가 이 1비트를 정해주지 않는다.**
정렬 전에는 `ang002` 가 표적 위상 0% 로 나와 "회전이 표적을 망친다"는 가짜 결론이 나올 뻔했다.
→ npz 에 정렬해서 내보냄(`gauge_flipped` 기록, 4각도 반전).

**(c) 위상 일관성의 정의를 바꿨다.** 처음엔 각도 *하나 안의* 동부호 비율을 셌는데,
기전의 예측량은 **각도들 *사이의* 일관성**이다(해마의 "표적 100% / off 59.6%" 대응물).
추가로 **구동 가중** — û 가 E₁ 에 수직이면 `Tdir≈0` 이라 그 세포는 자극을 안 받는데,
그런 배향의 위상 변화를 동조 손실로 세고 있었다.

### 결과

요청 필수조건 전부 통과 — 12각도 · M1 최대편차 **15.2%** · 전극조합 12/12 고유 ·
`montage_json` 만으로 E 벡터 독립 재현 오차 **2.7e-08** · 전 몽타주 i₁+i₂ = 2.0 mA.

**각도는 많을수록 좋지 않다.** 구동가중 분리력이 n=3 에서 최대:

| n | 최적 조합 | 표적 유지 | off 유지 | 분리력 |
|---:|---|---:|---:|---:|
| 2 | 004, 006 | 74.1% | 42.7% | 31.5%p |
| **3** | **004, 006, 009** | **67.6%** | **32.9%** | **34.7%p** |
| 4 | 003, 004, 006, 008 | 59.8% | 25.6% | 34.2%p |
| 8 | (8개) | 51.7% | 21.7% | 30.0%p |

요청서 §1-③ 의 전제("표적은 동조 유지, off 는 파괴")는 **부분적으로만** 성립한다.
각도를 늘리면 off 위상이 깨지지만 **표적 위상도 같이 깨진다.**

전기장 기준 분리력이 요청서가 문제로 지적한 17.8%p → **34.7%p** 로 약 2배가 됐다.
다만 해마 활성화함수 대조군(40.4%p)에는 못 미친다.

> ⚠️ **초기 보고 취소**: off 정의 수정 전 판에서는 n=3 에서 50.8%p 였고 "대조군을 넘었다"고
> 보고했다. 그 값은 off 를 GM 으로만 좁혀 부풀려진 것이다. **34.7%p 가 맞다.**

## 2. 리드필드 절대 스케일 감사 (`SCALE_AUDIT.md`)

계기: 심부 표적에서 총 2 mA 기준 엔벨로프가 1.22 V/m — 문헌 상한 0.2~0.8 V/m.

### 정상으로 확인된 것 (여기는 문제 없다)

| 항목 | 결과 |
|---|---|
| 좌표 디코딩 · 중첩 | E 벡터 독립 재현 오차 2.7e-08 |
| 정규화 규약 | `ΣI=0` 에서 Cz 기저 상쇄 — 자기정합 |
| 깊이 구조 | 피질p95/시상 = **3.4~4.0배** (문헌 3~5배) |
| 두개골 차단 | 뇌 양단 전위강하 **7~12%** (정상) |
| 표적 마스크 | 시상·STN·해마 위치·크기 타당 |

**구조는 멀쩡하고 절대 스케일만 어긋난다** → 상수배 보정이 원리적으로 가능하다.

### 과대 배수 — 독립 증거들

| 근거 | 배수 |
|---|---|
| Lamoš 2025 STN 쌍극 LFP 실측 | 2.3 |
| Violante 해마 문헌 | 3~6 |
| TI 시상 문헌 | 5~8 |
| 전류 플럭스 `∮σE·dA` (주입 1 mA 인데 통과 최대 2.9 mA) | 4.5~9.7 |
| 동심 4구 해석해 (S4L 자체 σ) | 5.5~5.9 |

### 기각한 원인 후보

- **주입전류 산출법** — `I = ∫σ|E|²dV` 는 V=1 V 에서 `P = 1·I_src` 라 **정확하다**
- **전도도** — Sim4Life 재료 DB(`data/XMaterials/Materials.db`, SQLite, **라이선스 불필요**)를
  직접 읽었다. IT'IS LF v5.0 은 GM **0.4191** · WM 0.3480 · CSF 1.879 · 두개골 0.0179 로
  문헌 관행(SimNIBS GM 0.276)보다 **높다**. σ 가 높으면 E 는 낮아지므로 원인이 못 된다
- **두개골 재료 오할당** — σ 를 0.0064↔0.32 로 **50배** 흔들어도 배수가 5.06→4.31 로만 이동
- **출력 단위 · 좌표 · 마스크 · 중첩**

### ★내가 틀렸다가 바로잡은 것

1. **"IT'IS 저주파 σ≈0.1 이 원인"** — 틀렸다. Sim4Life 에는 전도도가 4배 차이 나는 DB 가
   **둘**(`IT'IS LF` 스칼라 / `IT'IS` 분산모델) 있는데 내가 섞어 인용했다.
   LF v5.0 실측값은 0.4191 이다
2. **유효 전도도 역산 σ_eff ≈ 0.058 S/m** — 무효. 균질봉 가정이 전류 집중을 무시해
   **하한만** 준다. 하한 0.058 은 실제 0.419 와 모순되지 않아 아무것도 증명 못 한다
3. **GM/WM 경계 도약비 1.13 이 "어느 DB 와도 안 맞는다"** — 틀렸다. v5.0 참값 비가
   0.4191/0.3480 = **1.204** 라 측정이 **정상**이었다. 오히려 이게 재료 DB 판별의 근거다
4. **깊이 비교를 껍질 중앙값으로** — 축에서 먼 약한 지점이 섞여 얕을수록 과소평가되는
   인공물이 나왔다(배수 0.63→2.35 로 "구조 오류"처럼 보임). **축끼리 비교**로 정정하니
   배수 중앙 5.06, 단조 추세 없음

### ★기준모델 자체의 편향 (배수를 깎는다)

층별 옴손실을 적분해 대조하니 **내 기준모델에 구조적 편향**이 있다:

| | 뇌 옴손실 몫 | 총 R |
|---|---:|---:|
| 4구 팬텀 | **0.68%** | 2967 Ω |
| 리드필드 (T7, 1 mA) | **22.69%** | 1465 Ω |

팬텀 내역: 두피 92.3% · 두개골 6.8% · CSF 0.3% · 뇌 0.7%.
팬텀은 두개골이 뇌를 **빈틈없이 감싼** 닫힌 구조인데, 실제 머리에는 대후두공·안와·외이도가
있고 **목**이 두개골을 우회한다. 하필 T7/T8 은 얇은 측두골·외이도 근처다.

→ **해석해 기반 배수(5.5~5.9)는 상한으로만 읽어야 한다.**
두피 σ 를 공칭의 1/7 까지 흔들어도 3.84배로만 내려가 기준모델이 과도하게 전도성인 건
아니지만(팬텀 R 2967 Ω vs 리드필드 1465 Ω), 닫힌 두개골 편향은 남는다.

**정직한 현 상태(이 시점): 과대는 실재하나 배수는 2~6배로 폭이 넓다. 확정하려면 재솔브가 필요하다.**

> ★후속: 재솔브가 §6 에서 실행됐고 **2.1배가 확정됐다**(`inj_current` 가 `El. Loss Density`

## 3. off-target 정의 재검토

`config.NEURAL_LABELS = (LABEL_GM,)` 이라 off 가 **대뇌피질 회백질뿐**이었다.
**백질 981,723 복셀(뇌의 51%)** 과 심부핵 전부가 off 에서 빠진다. 심부 표적에서는
내포·주변 백질이 정확히 필드가 가장 센 곳이라, 최적화가 **거기에 쏟아부어도 벌점을 안 받는다.**

### 실험 — 지표가 아니라 몽타주가 바뀌는가

표적 5종에서 정의별로 최적 몽타주를 다시 찾았다(전극 풀은 표적 필드 세기로만 선정 —
off 정의와 무관하게 공정하도록).

| 표적 | GM만 vs GM+WM | GM+WM vs 뇌전체 |
|---|---|---|
| 시상L | **다름** | 다름 |
| 해마L | 동일 | 동일 |
| 조가비핵L | 동일 | 동일 |
| STN L | **다름** | 동일 |
| 편도체L | **다름** | 동일 |

**3/5 에서 승자가 바뀐다.** STN 이 가장 극적 — 공통 자(뇌 전체 off)로 재평가하면:

| 탐색 시 off 정의 | M1 | M2 | M3 |
|---|---:|---:|---:|
| GM만 (구) | 1.186 | 2.35 | **10.8%** |
| GM+WM | 0.196 | 5.34 | **0.3%** |

GM만으로 탐색한 승자는 실제 누출이 **36배** 나쁜데, 자기 잣대로 재면 5.7% 라 그럴듯해 보인다.

**gm_wm ≡ brain** (5표적 전부 승자 동일) → **백질 누락이 원인의 전부**고 심부핵 추가는 무의미.

### 구현

- `config.OFF_LABEL_SETS` = `gm` / `gm_wm` / `brain`, `OFF_DEFAULT = "gm_wm"`
- `Target(..., off_labels=...)` 인자, `self.off_def` 에 사용 정의 기록 → `summary()` 로 노출
- `NEURAL_LABELS` 는 **건드리지 않았다** — `validate_tiplite.py` 의 tip.lite 정합 검증이
  여기 의존하고, `from_sphere(restrict_neural=True)` 는 표적 제한용이라 의미가 다르다.
  실행해 수치 동일함을 확인했다
- 과거 수치 재현은 `Target(..., off_labels="gm")`

## 4. WSL NEURON 이식 검증

메모리 `seqti-integrated-pipeline` 의 "유일한 물리적 부재"였던 항목. 판정 기준은
`0804_NEURON_result/thresholds.npz` 재현(맥 결과가 정답지).

환경: Ubuntu 26.04 · NEURON 9.0.1 · numpy 2.2.5 · **scipy 1.15.3**(메모리엔 없다고 기록돼
있었으나 생겼다) · 22코어/31GB · `/mnt/c` 직접 접근.
하네스 전체(`fiber_pop.py`·`AXNODE.mod`·`mrg_src/`)가 `~/neuron_handoff/` 에 이식돼 있고
`.mod` 도 컴파일 완료(`x86_64/libnrnmech.so`). MRG 는 `AXNODE.mod` 하나만 필요하다
(MYSA/FLUT/STIN 은 수동 — 원본 McIntyre 구현과 동일).

**결과**

| | |
|---|---|
| 역치 완전일치 | **123/123 섬유 × 3 몽타주** |
| 개시위치 편차 | **0.0000 mm** |

비단조는 문제가 아니라 **재현의 추가 증거**다(발화→블록→재발화). 코드도 위반 시

## 5. baseline VS 둔감성 — 가설 A 확정

관찰: 두 판의 baseline 몽타주가 다른데 표적 VS 가 0.1790 vs 0.1785 로 거의 같다.
가설 A(두 몽타주가 실제로 같은 필드) vs B(VS 가 둔감).

**NEURON 없이 필드로 갈렸다.** 두 npz 의 `E1vec/E2vec` 는 같은 850 위치 값이라 직접 비교 가능:

```
구판 baseline : ('C5','Oz') x ('F7','T8')
현행 baseline : ('Oz','C5') x ('T8','F9')      ← 전극 3/4 공유, F7→F9 는 인접
```

| | 값 |
|---|---|
| 표적 엔벨로프 상관 | **0.995** (중앙 상대차 2.0%) |
| off 엔벨로프 상관 | 0.997 (0.1%) |
| E 벡터 방향 \|cos\| | 표적 E1 **1.000** · E2 0.997 |

→ **가설 A.** 지표 둔감성이 아니다. 다만 이건 "왜 같았나"만 설명하고 **"VS 가 민감한가"는
증명하지 못한다** — 그건 일부러 크게 다른 몽타주로 재야 한다(미실시).

## 6. Sim4Life 헤드리스 팬텀 솔브 (진행 중)

목적: **머리 모델 없이** 정규화 사슬만 시험한다. 같은 팬텀을
(a) 1 V 기저 + `∫σ|E|²dV` 정규화 · (b) 전류원 ±1 mA 로 두 번 풀어 대조.
닫힌 두개골 편향이 양쪽에 똑같이 걸려 **상쇄**되므로 §2 의 기준모델 문제를 우회한다.

### 확인된 것

- 지오메트리 4구 껍질 — `xm.Subtract([outer, inner])`, 부피 오차 **0.00%**
- 단위 — 입력 수치는 **mm**, 솔버 결과 격자는 **m** (원본 리드필드 규약과 일치)
- 격자 2 mm → 140×148×140 = 2.9 MCells
- **헤드리스 솔버 실행 확인** — QS_SOLVER 체크아웃 → iSolve → 정상 종료

### ★함정 확정 — 같은 엔티티에 재료 + 경계조건 동시 부여 금지

`WriteInputFile()` 의 `Failure type: network` 는 **가짜 문구**(예외 클래스 기본값).
로그 원문은 `Can't create attribute 'A47CB6B1' / attribute already exists`.
이분 탐색으로 확정:

| BC 개수 | 전극에 재료 | WriteInputFile |
|---:|---|---|
| 0 | O | 성공 |
| 1 | O | **실패** |
| 2 | O | **실패** |
| 2 | **X** | 성공 |

→ **전극은 재료 도메인이 아니라 경계로만** 다뤄야 한다.
PIPELINE.md 함정 2번("Dirichlet 을 솔리드 바디에 부여")의 실체로 보인다 — 문서 갱신 필요.

### ★함정 2 해결 (후속 세션) — 복셀 장면이 비어 있던 원인

증상: 솔브가 2초에 끝나고 출력 전부 NaN, `Voxel Scene 894 bytes`, `no used degrees of freedom`.
**두 가지가 겹친 것이었다.**

1. **복셀러 설정이 어느 엔티티에도 안 붙었다.** 재료를 준 엔티티라도 복셀러 설정이
   따로 붙어야 복셀 장면에 들어간다. **새로 만들지 말고 있는 것을 쓴다**:
   ```python
   vox = next(s for s in sim.AllSettings if type(s).__name__ == "AutomaticVoxelerSettings")
   sim.Add(vox, [엔티티들])
   ```
   `AddAutomaticVoxelerSettings(...)` 가 던지는 `"incompatible with this type of simulation"` 은
   **오도하는 문구**다. 실제 뜻은 "이미 그 설정이 있다"이다
   (`_api/_simwrappers_simulation.py:183`).
2. **시뮬레이션을 문서에 늦게 등록했다.** `CreateVoxels()` 는 내부에서 문서를 먼저 저장한 뒤
   복셀링하는데, `doc.AllSimulations.Add(sim)` 를 그 뒤에 불러 문서에 없는 시뮬을 복셀링했다.

**고친 순서**: 생성 → **문서 등록** → 재료 → 경계 → 복셀러 부착 → 격자 → 센서
→ `UpdateGrid` → `CreateVoxels` → `WriteInputFile` → `RunSimulation`

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 자유도 | **0** | **2,962,269** |
| 인식된 재료 | Background 뿐 | 5종 전부 |
| 솔브 | 2초, NaN | **29초, 정상** |

### ★★본론 결과 — 정규화 전류가 2.1배 작다

1 V 구동에서 주입전류를 세 방법으로 쟀다:

| 양 | 값 |
|---|---:|
| `∫(El. Loss Density)dV` — **리드필드가 쓰는 값** | **0.31595 mA** |
| `∫Re(J·E*)dV` (= `∫σ\|E\|²dV`) | 0.63190 mA |
| **전하보존 실측** `∫Jx dA` (평면 5곳 편차 **0.000%**) | **0.66349 mA** |
| 실측 ÷ 손실밀도 | **2.1000** |

**기전**: S4L 의 E·J 는 `RmsFactor=0.7071` 즉 **최대 진폭** 저장인데, `El. Loss Density` 는
시간평균 규약 **σ\|E\|²/2** 다(`RmsFactor=1.0`). 실측으로 `∫Re(J·E*)dV ÷ ∫LossDensity dV
= 2.0000` **정확히 2배** 확인.

`tip/tip/leadfield_gen.py` 의 `injected_current()` 는 **docstring 에 `I=∫σ|E|²dV` 라고
옳게 적어 놓고 구현은 그 절반인 `El. Loss Density` 를 적분한다.** 파일 머리말의
"independently confirmed (inj_current.json 과 float64 일치)"는 **같은 잘못된 양끼리의
대조**라 오류를 못 걸러냈다.

→ `unitnorm = 1e-3/I_inj` 가 2.1배 크고 **정규화 필드가 전부 2.1배 크다.**
1 mA 환산 중심 \|E\|: 현재 방식 8.1203 vs 실측정규화 **3.8668 V/m**.

**§2 의 4~6배 중 2.1배가 이것으로 설명된다. 남은 2~3배는 미해결.**

### 새로 발견한 함정

  Flux 는 우변 기여가 0 이 되어 해가 통째로 0. 원래 설계한 (b) 전류원 대조는 이 경로로 불가
- **`TreatAsPort=True` 는 시뮬레이션을 무효로 만들고 되돌려도 복구되지 않는다**
- `NeumannValue` 는 읽기 전용

## 7. 성능 문제 둘

- **`optimize_classic` 이 70전극에서 사실상 멈춤** — 별도 작업으로 수정돼
  **9.9분 / 피크 1.1 GB** 로 돌아간다 (후보 3,575만 = 메타 2,750,685 × 비율 13).
  24전극 대조: **138.0s / 1.5 GB → 10.6s / 0.57 GB**, `best` 와 몽타주 목록 전체가
  **부동소수 오차 없이 완전히 일치(bit-exact)**
  (7케이스: STN·시상·해마 × K=12~24, `min_dist_mm`·`pctl=70`·비대칭가중·`exact` 포함).

  > ⚠️ 이 항목의 초판은 "**9.6분 / 0.6 GB**" 였다. 0.6 GB 는 **24전극** 값이고 70전극
  > 실측 피크는 1.1 GB 다. 측정 전 추정치가 옮겨온 것이라 바로잡는다.

  ★**원인이 둘이었고, 처음 지목한 쪽은 시간의 주범이 아니었다.** 파이썬 튜플 누적은
  **RAM 만** 설명한다 — 24전극 계측에서 numpy 커널 134.98s vs 튜플 누적 **0.28s**.
  시간은 비율 루프가 `ti.tmax` 를 비율마다 다시 불러 `(b,N,3)` 벡터연산을 13번
  반복한 것이었다(누적만 고쳤다면 195분 → 194분). 해법은 **두 반송파의 내적·외적량만
  남긴 스칼라 4조 꼴**(함수 `ti.gram3`/`ti.tmax_gram`; 앞 셋이 그람 행렬 성분이라
  이름을 gram 으로 붙였다): Tmax 닫힌해는 `(|E1|²,|E2|²,|E1·E2|,|E1×E2|²)` 네 스칼라장
  만으로 쓰이고 E2 를 r 배 하면 `(u, r²w, r·a, r²c2)` 로 스케일만 바뀌므로, 벡터연산이
  **청크당 1회**로 줄고 비율 루프는 `(b,N)` 스칼라만 남는다(실제 리드필드 대조 최대
  상대오차 7.6e-14). 상세·함정은 메모리 `seqti-perf` §4
- **각도 스윕 114분 → 2분** (§1)
